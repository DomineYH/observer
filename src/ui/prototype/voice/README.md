# PROTOTYPE — 교신 문장을 말했을 때 후보 인식기가 듣는 글 (#177)

버려도 되는 페이지다. 제품 코드가 아니고 main에 합치지 않는다.

**질문:** 소유자가 교신 문장을 직접 말했을 때 후보 인식기는 무엇을 듣는가. 어느 인식기가 쓸 만한가를 문서가 아니라 잰 값으로 답한다.

## 돌리는 법

WSL에서(의존성이 리눅스용으로 설치돼 있다):

```sh
cd /mnt/c/dev/observer-m4-voice
npm run proto:voice
```

그다음 **Windows Chrome**(기준 데스크톱)에서 <http://localhost:5177/prototype-voice.html>을 연다. 시크릿 창은 쓰지 않는다(vosk가 모델을 저장하다 멈춘다).

1. "모델 미리 받기"를 누른다. Whisper는 처음 한 번 Hugging Face에서 받는다(tiny 39 MiB, base 73 MiB).
2. "내장·기기 안 한국어 설치"를 누른다(Chrome 139+). 안 되면 그 칸은 오류 글로 남는다.
3. 화면의 문장을 스페이스(또는 단추)를 누른 채 읽고 뗀다. 인식기마다 들은 글과 걸린 시간이 표에 선다. →로 다음 문장. 문장은 25개다.
4. "결과 내려받기"로 JSON을 받는다. "녹음 포함"을 켜 두면 같은 소리로 다른 인식기를 나중에 다시 잴 수 있다. 목소리가 든 파일이라 저장소에 올리지 않는다(`.gitignore`에 있다).

Whisper를 돌리는 곳을 `webgpu`로 바꿔 한 번 더 재면 속도 차이를 볼 수 있다.

## 페이지가 하는 일

- 문장은 게임의 문장 만들기(`radioSentence`)가 교신 문법에서 만든다(`sentences.ts`). 문형마다 하나 이상이고 한 자리씩 읽는 수, 백·십 단위, 발수, 음성 문자, 복창이 들어 있다.
- 말하는 동안 16 kHz로 녹음하고, 내장·클라우드 인식은 같은 마이크를 실시간으로 듣는다. 떼면 녹음 하나를 나머지 인식기에 차례로 넣는다(시간이 서로 섞이지 않게 하나씩).
- 내장·기기 안 모드는 녹음을 다시 틀어서 듣게 한다(`start(track)`). 이 호출은 헤드리스 Chrome에서 확인하지 못했다.
- 초록 칸은 띄어쓰기와 문장부호를 뺀 글이 말한 문장과 같은 칸이다.

- 내장 인식 둘은 헤드리스 Chrome에서 `audio-capture`와 `language-not-supported` 오류였다. 실제 Chrome에서만 잴 수 있다.

## 합성 음성으로 잰 것 (2026-11-23)

소유자가 녹음을 프로젝트 뒤로 미뤘다. 그래서 Windows의 한국어 합성 음성(Microsoft Heami, `tts.ps1`)으로 문장 25개를 두 빠르기(보통 `r0`, 빠름 `r3`)로 만들어 쟀다. **사람 목소리가 아니다.** 인식기 사이의 차이와 틀리는 꼴만 믿는다. 이 PC가 기준 데스크톱(i5-10210U)이다. 자료와 스크립트는 `measured/`에 있다(소리 파일은 없다. `tts.ps1`로 다시 만든다).

| 인식기 | 곳 | 보통: 글이 나옴 / 글자까지 같음 | 빠름 | 말이 끝난 뒤 걸린 시간(가운데 값 / 최대) |
| --- | --- | --- | --- | --- |
| Whisper tiny (wasm 한 스레드) | WSL 헤드리스 Chrome 156 | 25 / 0 | 25 / 0 | 3.6초 / 15.5초 |
| Whisper base (wasm 한 스레드) | 같음 | 25 / 0 | 25 / 1 | 7.5초 / 14.9초 |
| vosk small-ko, 문법 없음 | 같음 | 25 / 0 | 25 / 0 | 7.4초 / 10.0초 |
| vosk small-ko + 낱말 문법(낱말 그대로) | 같음 | 25 / 1 | 25 / 0 | 1.7초 / 3.3초 |
| vosk small-ko + 낱말 문법(없는 낱말을 조각으로) | 같음 | 25 / 6 | 25 / 4 | 1.2초 / 3.0초 |
| Chrome 내장·클라우드 (`start(track)`) | Windows Chrome 157 | 14 / 0 | 4 / 0 | 0.1초 / 0.2초 |
| Chrome 내장·기기 안 | Windows Chrome 157 | 못 잼 | 못 잼 | — |

- **Whisper tiny·base:** 교신 낱말을 다른 낱말로 적고("길어기", "흐력사", "73만 원 하나요") 같은 말을 되풀이하는 헛말이 두 번 나왔다.
- **vosk + 낱말 문법:** 한 자리씩 읽는 수를 거의 그대로 듣는다("넷 오 아홉 아홉 삼 오 공 둘"). 모델에 없는 낱말 23개는 **모델에 있는 조각으로 나눠 주면 듣는다**(`exp-vosk.mjs`): 효력 사, 임무 끝, 좌 로, 우 로, 표적 번호, 사격지휘 통보, 순발 신관, 접근 신관, 위험 근접, 지명 사, 잠깐 대기, 마감 탄, 전 이, 여기 는, 보병 소대, 공격 중인, 동 제원, 한 개, 두 대, 세 문. 남은 틀림은 한 글자 조각 때문에 생긴다("이상" → "이 삼"·"미상", "공공" → "공격", "좌로" → "잠깐"). 문장 25개의 낱말을 한꺼번에 문법으로 준 값이다.
- **Chrome 내장·클라우드:** 녹음을 `start(track)`으로 들려주면 된다(Chrome 157). 그러나 `stop()` 뒤 최종 결과가 오지 않고 중간 결과만 남은 것이 100번 가운데 56번, 아무것도 없는 것이 8번이다(말이 끝나고 1.5초 기다린 뒤 `stop()`). 온 글은 교신 낱말을 꽤 맞히지만 수를 제멋대로 적는다: "넷 여섯 5 73115", "넷050-3009", "하나 002", "하나 120"(하나백둘십), "2백", "햇빛"(넷백), "선발"(삼발), "자로"·"바로"(좌로), "이무근"(임무끝), "인상"(이상). 다른 후보(`maxAlternatives`)에 맞는 글이 든 때가 있다.
- **Chrome 내장·기기 안:** `available()`이 `downloadable`이었고 `install()`은 두 번 시도해 10분 넘게, 4분 넘게 `downloading`에서 끝나지 않았다. 재지 못했다.
- 소리가 Google로 가는 것은 내장·클라우드뿐이다(합성 음성이라 개인 정보는 없다).
