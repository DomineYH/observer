# 실전에서만 읽는 값은 실전 자료 판이 덮는다

실전 모드에서만 읽는 값은 세 곳에 있다: 실전 수치(규칙의 수 열셋), 시나리오마다의 증원, 포 프로파일마다의 진지 변환 시간. 값은 주인 곁에 둔다. 증원은 그 시나리오의 파일에, 진지 변환 시간은 그 포 프로파일에 적는다. 그러나 버전은 주인의 것을 쓰지 않는다. 정수 하나인 실전 자료 판이 셋을 모두 덮고, 그 값이 하나라도 바뀌면 실전 자료 판만 오른다. 시나리오 버전, 포 프로파일 버전, `simVersion`은 그대로다.

실전 자료 판은 실전 판의 재생 자료 머리에만 `combatDataVersion`으로 실린다. 훈련·표준 판의 머리에는 없고, 있으면 형식 검사가 거부한다. 재생기는 머리의 값이 넘겨받은 실전 수치의 판과 다르면 재생하지 않는다.

까닭은 실전의 숫자가 사람 검수 뒤에 고쳐질 것이 예정된 값이기 때문이다(레이저 한도, 증원의 규모와 시각, 적 포병 사격의 시간, 체류 한도, 진지 변환 시간). 그것을 고칠 때 기본 판(기본 시나리오 + 기본 포 + 훈련·표준)의 골든 기록과 지금까지의 기록이 흔들리면 안 된다. 증원이 시나리오 버전에, 진지 변환 시간이 포 프로파일 버전에 들면 실전의 숫자 하나를 고칠 때마다 표준 판의 기록까지 옛 버전이 된다.

## Considered Options

- **주인의 버전이 받기**(증원 → 시나리오 버전, 진지 변환 시간 → 포 프로파일 버전): 규칙이 "값이 바뀌면 그 자료의 버전"으로 하나지만, 실전에서만 읽는 값을 고쳐도 훈련·표준 판의 재생 자료 머리가 바뀌고 그 골든을 다시 만들어야 한다.
- **실전 값을 한 파일에 모으기**: 판과 파일이 하나로 맞지만 증원이 시나리오에서, 진지 변환 시간이 포에서 떨어진다. 새 시나리오를 쓸 때 파일 둘을 고쳐야 하고 한쪽을 잊기 쉽다.
- **시뮬레이션 코드의 상수**: 고칠 때마다 `simVersion`이 오르고 모든 골든을 다시 만든다.
- **조각마다 판**(시나리오마다의 실전 판, 포마다의 실전 판, 실전 수치의 판): 증원 하나를 고쳐도 다른 시나리오의 실전 기록이 살아남지만, 머리에 실을 수가 셋이 되고 재생기가 견줄 것도 셋이 된다. 실전 수치는 어차피 모든 실전 판에 닿는다.

## Consequences

- 실전의 수 하나를 고치면 모든 시나리오와 모든 포의 실전 기록이 옛 판의 기록이 된다. 다시 만드는 골든은 실전 골든뿐이다.
- 새 시나리오나 새 포 프로파일을 더하는 것은 실전 자료 판을 올리지 않는다. 있던 값이 바뀌지 않았기 때문이다.
- 시나리오에 증원이, 포 프로파일에 진지 변환 시간이 처음 채워져도 그 시나리오와 프로파일의 버전은 그대로다(`base@1`).
- 내용과 판의 짝은 조각마다 한 줄인 기대값이 지킨다: 실전 수치, 시나리오마다의 증원, 포마다의 진지 변환 시간. 열쇠에 실전 자료 판이 들어 있어 값을 고치면 판을 올리고 줄을 새로 적어야만 초록이 된다.
- 작전 준비 시간 제한(실전의 300초)은 화면의 수라 실전 수치에도 실전 자료 판에도 들지 않는다.
- 실전의 규칙(코드)은 실전 자료 판이 덮지 않는다. 그것은 `simVersion`의 일이다(ADR 0009·0016).
