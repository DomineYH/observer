# 포 프로파일은 포와 탄이 정하는 수만 담고 1차식 계수로 적는다

M3는 포 수치를 시뮬레이션 코드에서 포 프로파일로 옮긴다. 프로파일에는 포와 탄이 정하는 수만 둔다: 최대 사거리, 비과시간과 사거리·편의 공산오차의 1차식 계수, 방렬 좌표 목록(문수는 그 길이), 효력사 간격과 흔들림, 살상 반경. 절차(수정탄, 신관, 기러기의 응답 시간), 표적의 반응, 점수, 안전 거리(위험근접 600 m, 아군 피해), 비표준 조건 오차와 기상 잔차는 모든 포에 같은 게임 규칙으로 코드에 남는다. 수는 코드에 적혀 있던 십진 수 그대로이고 식의 계산 순서는 코드가 지킨다. 그래서 `base` 프로파일로 옮긴 뒤에도 골든 기록과 `simVersion`이 그대로다.

## Considered Options

- **거리별 표 + 보간**: 실제 포의 곡선에 가깝게 만들 수 있다. 그러나 임의 거리에서 지금 1차식과 비트까지 같다는 보장이 없어 골든이 바뀔 수 있고, 거리별 공산오차·비과시간은 공개 값이 없어 표를 채우면 지어낸 사표가 된다(ADR 0013).
- **세 파일의 숫자를 전부 자료로**: 손잡이가 많아지지만 응답 시간·판단 확률·점수까지 포마다 달라질 수 있어 포 넷마다 검수할 수가 수십 개가 된다.
- **판 도중의 사거리 규칙("사격 불가" 응답)**: 현실적이지만 교신 상태 기계에 새 갈래와 출처 없는 문구가 들어가고, 판 전 검사를 통과한 판에서는 일어나지 않는다. 최대 사거리는 판 전 검사에만 쓴다.
- **정수·고정 소수로 적기**: 자료가 깔끔해 보이지만 나눗셈이 하나 더 들어가 마지막 비트가 달라질 수 있다.

## Consequences

- 포마다 달라질 수 있는 것은 프로파일의 필드뿐이다. 다른 수를 포마다 바꾸려면 규칙을 고치는 새 결정이 필요하다.
- 프로파일은 낱말을 갖지 않는다(ADR 0004). 포의 이름과 소개는 프로파일 버전 밖의 글이다.
- 시뮬레이션이 읽지 않는 값(최대 사거리)도 프로파일의 값이다.
- 방렬 목록의 순서는 난수를 뽑는 순서라 프로파일의 일부다.
- ADR 0009의 "포 제원이 바뀌는 변경은 `simVersion`을 올린다"를 프로파일 버전과 어떻게 맞출지는 [결정성과 버전](https://github.com/DomineYH/observer/issues/126)이 정한다.
