# 실전 모드는 판을 만드는 값이고 입력으로 드나들지 않는다

훈련과 표준은 판 도중에 `mode` 입력으로 오간다(데모 그대로, ADR 0003의 입력 기록에 남는다). 실전은 그렇게 하지 않는다. 실전은 시뮬레이션을 만들 때 주는 값이고, 작전 준비에서 실전을 고르거나 실전에서 벗어나면 판을 새로 만든다(연습의 기상 변경, 포 고르기와 같은 길). `mode` 입력의 값은 훈련과 표준 둘뿐이며, 실전 판에서 `mode` 입력은 받아들여지지 않는다. 작전 개시 뒤에는 실전으로 올라갈 수도, 실전에서 내려갈 수도 없다.

까닭은 실전에서만 읽는 값이 시뮬레이션을 만들 때 정해지기 때문이다. 증원은 시나리오 스트림의 둘째 차례(원래 적과 아군 병사 뒤)로 한 번 뽑고, 실전 수치는 실전 판을 만들 때만 시뮬레이션에 들어간다. 그래야 같은 시드의 원래 적·아군 배치가 표준과 글자까지 같고, 기본 판(기본 시나리오 + 기본 포 + 훈련·표준)의 골든 기록이 바뀌지 않는다.

상태 해시는 이 구분에 기댄다. 모드 목록에서 실전은 끝에 더한다(해시가 모드를 목록 안의 번호로 읽으므로 훈련·표준의 값이 그대로다). 실전이 상태에 더하는 것(쓴 레이저 횟수, 노출, 적 포병 사격, 포대의 진지 변환, 임무마다의 밀린 복창)은 해시의 끝, 점수 뒤에 한 덩이로, 실전일 때만, 정해진 차례로 넣는다. 지금 구조(임무, 부대)에 실전이 더한 필드도 제자리가 아니라 그 덩이에서 넣는다. 예약 이벤트의 종류와 쏘는 쪽처럼 번호로 읽는 목록은 끝에만 더한다. 그래서 훈련·표준 판에서 해시에 들어가는 바이트열은 실전이 생기기 전과 같고, M3는 `simVersion`을 올리지 않았다(17).

## Considered Options

- **실전에서 훈련·표준으로 내려가는 입력**: 증원과 실전 수치는 이미 판에 들어 있어 뺄 수 없다. 남겨 두면 "실전의 규칙이 도는 훈련 기록"이 생겨 판 기록의 모드가 규칙을 말해 주지 못한다.
- **훈련↔표준도 판을 만드는 값으로 통일**: 규칙은 하나가 되지만, 0틱의 `mode` 입력을 가진 지금의 재생 자료(골든 둘 포함)가 무효가 되고 "작전 중에 훈련을 켜면 훈련 기록"이라는 데모의 동작이 사라진다.
- **판을 열기 전의 선택 화면에서만 실전을 고르기**: 작전 준비에서 판을 새로 만드는 길이 이미 있어 화면을 기다릴 까닭이 없다.
- **실전의 상태를 모든 모드에서 해시에 넣기**: 해시의 꼴이 하나가 되지만 훈련·표준 판의 중간 상태 해시가 전부 바뀌어 `simVersion`을 올리고 모든 골든을 다시 만들어야 한다. M3는 골든 기록 7개가 한 글자도 바뀌지 않는 것을 "지금과 같은 결과"의 증거로 삼았다.
- **실전의 필드를 제자리에서 조건부로 넣기**: 결과는 같지만 "실전에서만"이 여러 곳에 흩어져, 훈련·표준의 바이트열이 그대로인지를 한 군데만 보고 알 수 없다.

## Consequences

- 실전 판의 재생 자료는 머리의 `mode`만 실전이고 `mode` 입력이 하나도 없다. 훈련·표준 판의 재생 자료는 지금 그대로다.
- 실전 판은 훈련 기록이 될 수 없고, 훈련·표준 판은 실전 기록이 될 수 없다. 판 기록의 모드가 실전인 것과 재생 자료 머리의 모드가 실전인 것은 늘 같다.
- 실전을 그만두려면 판을 버리고 새로 열어야 한다.
- 일시정지 없음과 작전 준비 시간 제한은 화면의 규칙이다. 시뮬레이션, 입력 기록, 재생 검증은 그것을 모른다(ADR 0003: 일시정지와 배속은 기록하지 않는다).
- 실전에 새 상태를 더하는 변경은 그 덩이의 끝에 더한다. 훈련·표준이 읽는 상태를 더하는 변경은 이 길을 쓸 수 없고 `simVersion`을 올린다.
- 실전 규칙이 만들어지는 동안(M3)에는 실전 결과를 바꾸는 코드 변경이 `simVersion`을 올리지 않았다. M3의 통과 관문 뒤에는 실전도 다른 모드와 같다: 결과를 바꾸는 변경은 `simVersion`을 올린다.
