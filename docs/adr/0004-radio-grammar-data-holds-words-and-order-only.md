# 교신 문법 데이터는 낱말과 순서만 갖고, 절차와 읽기 규칙은 코드에 둔다

PRD 7.2는 교신 문구를 "교신 문법 JSON — 슬롯 문법으로 입력기·음성 인식·서버 검증이 공유"하는 자료로 그렸다. M1은 그보다 좁게 잡는다. 교신 문법 데이터는 `content/`의 TS 상수이고(함수·HTML 없이 JSON으로 그대로 옮길 수 있는 값만), 교신 한 마디의 종류마다 문형(고정 낱말·슬롯·선택 요소의 조각 배열)과 슬롯 값의 낱말, 출처 표시와 검수 필요 여부만 담는다. 어떤 입력을 언제 받는지, 값의 범위와 스냅, 끝말 선택은 시뮬레이션(`sim/radio/`)의 것이고, 숫자 읽기 규칙 네 가지는 이름 붙은 코드다. 문장은 시뮬레이션 밖의 순수 함수가 `(말한 쪽, 종류, 슬롯 값, 끝말)`과 호출부호만으로 만든다. 그래서 문구를 통째로 갈아 끼워도 재생 결과가 달라지지 않고, 서버 재생 검증은 이 데이터를 쓰지 않는다(입력 기록에는 열거형과 정수만 있다).

## Considered Options

- **틀 문자열(`"방향 {dir}, {corr}, 효력사"`)**: 쓰기는 쉽지만 "방향은 첫 수정에만" 같은 선택 요소를 표현하려면 자체 문법이 필요하고, M4 음성 입력이 문장을 거꾸로 풀 때 다시 파싱해야 한다.
- **읽기 규칙도 데이터로**: 포병 숫자 읽기를 데이터로 표현하면 작은 언어를 만들게 된다. 규칙은 네 개뿐이고 바뀌는 것은 낱말이다.
- **데이터가 절차까지(슬롯 문법이 입력 순서·필수 여부를 정함)**: 문구를 바꾸면 시뮬레이션 결과가 달라질 수 있어 `simVersion`과 재생 검증이 문법 버전에 묶인다.
- **처음부터 JSON 파일**: 시나리오·포 제원과 같이 M1은 TS 상수로 타입 검사를 받는다. 함수만 금지하면 옮기는 일은 복사다.

## Consequences

- 슬롯 값은 닫힌 열거형이나 범위가 정해진 정수뿐이다. 표적성질은 한 덩어리 문자열이 아니라 활동·종류·규모 슬롯으로 나뉜다.
- 관측자 호출부호는 계정이 주는 자유 문자열이므로 슬롯이 아니다. 문장을 만들 때 따로 넘기고, 시뮬레이션과 입력 기록에는 들어가지 않는다.
- 같은 말한 쪽 안에서 서로 다른 `(종류, 슬롯 값)`이 같은 문장을 만들면 안 된다. 테스트로 지킨다.
- 훈련 모드의 아라비아 숫자 병기는 문장 안 HTML이 아니라 별도 조각으로 나온다. 음성 출력은 병기를 읽지 않는다.
- 시스템 알림·훈련 힌트·입력기 안내는 이 데이터가 아니라 `ui/` 문구다.
