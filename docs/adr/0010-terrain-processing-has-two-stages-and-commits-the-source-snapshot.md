# 지형 가공은 두 단계이고 원자료 스냅샷을 커밋한다

실제 지형은 원격 공개 자료(GEDTM30, ESA WorldCover, OpenStreetMap)에서 만든다. OpenStreetMap은 날마다 바뀌고 원격 호스트는 우리가 고정할 수 없으므로, 받으면서 가공하면 같은 결과를 다시 만들 수 없다. 그래서 가공을 둘로 가른다. 받기(네트워크)는 원천을 전장의 격자에 맞춰 읽어 원자료 스냅샷으로 얼리고 투영도 여기서 끝낸다. 가공(오프라인)은 스냅샷과 가공 설정만 읽어 지형 파일, 지형 기대값, 가공 자료 머리, 가공 기록을 쓴다. 스냅샷까지 모두 저장소에 커밋하고, CI가 가공을 다시 돌려 커밋된 가공 자료와 견준다. 견주는 것은 압축을 푼 내용과 지형 해시다. 압축된 바이트는 도구 판에 달릴 수 있어 커밋된 파일을 정본으로 둔다.

## Considered Options

- **스냅샷을 저장소 밖에 두고 체크섬만 커밋**: 저장소가 가볍지만 스냅샷을 잃으면 그 판을 다시 못 만들고 CI가 견줄 수 없다.
- **CI에서 받기까지 돌리기**: 저장소에 원자료가 없지만 남의 서버 상태가 CI를 좌우한다.
- **GDAL·Python으로 가공**: 래스터 도구가 익숙하지만 면적 재표본이 마디 격자와 어긋나고, 풀기 함수와 지형 해시의 두 번째 구현이 생긴다. 가공은 앱의 풀기 함수와 지형 해시를 그대로 부르는 Node + TypeScript 하나다.

## Consequences

- 저장소가 전장마다 약 2 MB와 지형 판마다 1.5 MB 이하로 자란다.
- OpenStreetMap 추출본이 Git 기록에 남으므로 저장소를 공개하기 전에 ODbL 조건을 확인해야 한다.
- 벌채 원 같은 가공 설정만 바뀐 판은 네트워크 없이 다시 만들어진다.
- 지형 판은 사람이 올린다. 같은 판에 다른 내용이 나오면 가공이 쓰기를 거부한다.
