# 교신 상태 기계는 시뮬레이션 안에 두고, 시뮬레이션은 값만 받는다

PRD 7.5는 `sim/`과 `radio/`를 나란한 모듈로 권했지만, M1은 교신 상태 기계를 시뮬레이션의 내부 이음매(`sim/radio/`)로 둔다. 교신 절차는 예약 이벤트 큐·FDC 난수 스트림·점수·탄착 콜백을 시뮬레이션과 공유하고 M6 서버 재생에서 함께 돌아야 하므로, 둘을 나란히 두면 두 모듈 사이 인터페이스가 구현만큼 넓어진다. 밖에서 보이는 것은 시뮬레이션 하나다: 생성 인자(시드·시나리오·포 제원·지형 자료·기상 값·모드)를 **완성된 값**으로 받고, 입력을 받아 한 틱 진행하며, 읽기 전용 상태와 사건을 내놓는다. 시뮬레이션은 어댑터를 부르지 않고 문구 문자열·HTML·소리를 만들지 않는다.

## Considered Options

- **`sim/`과 `radio/`를 나란히(PRD 권장)**: 교신 문구를 갈아 끼우기 쉬워 보이지만, 갈아 끼울 것은 문구 데이터이지 상태 기계가 아니다. 문구는 사건(종류 + 슬롯)을 받아 시뮬레이션 밖에서 만든다.
- **시뮬레이션이 지형·기상 어댑터를 주입받아 직접 호출**: 비동기 호출과 실패가 결정적 틱 안으로 들어온다. 이음매를 한 단계 앞(지형 원천·기상 원천)에 두고 결과 값만 넘긴다.

## Consequences

- 재생은 별도 모듈이 아니다. 같은 생성 인자와 같은 입력 열을 시뮬레이션에 다시 넣는 것이 재생이다.
- 입력은 한 문으로만 들어가므로, 데모의 입력 기록 누락(위치 보고 생략, 기상 변경 등)은 구조상 생길 수 없다. 기상 값은 생성 인자이므로 기록에 남겨야 재생된다.
- mock 지형 생성기는 서버 재생에도 쓰이므로 시뮬레이션과 같은 결정성·DOM 금지 규칙을 따른다.
