# 결정적 수학은 fdlibm 포팅이고, 결과 변경은 골든 기록과 simVersion으로 묶는다

시뮬레이션의 초월 함수(exp·log·sin·cos·tan·atan2)는 `sim/math.ts`에 fdlibm을 순수 TypeScript로 옮겨 쓴다(약 1 ULP). 사칙연산만 쓰는 다항식 근사(0 A.D. 방식, 약 10⁻⁶)도 엔진 간 결정성은 같지만, 포팅 쪽은 데모의 `Math.*`와 사실상 같은 값을 내므로 PRD 6장 수치와 몬테카를로 결과(71%/85% 등)를 다시 맞출 필요가 없고, "`Math.*`와 1 ULP 이내 + 고정 입력의 비트 출력 표"라는 검증 기준이 생긴다. 이 함수들의 출력은 모든 판의 결과에 들어가므로, 한 번 정하면 바꾸는 순간 모든 골든 기록과 `simVersion`이 바뀐다.

결과가 달라지는 변경은 한 가지 길로만 통과한다. 골든 기록은 M1 빌드가 각본 입력으로 만든 재생 자료 + 200틱마다의 상태 해시 + 최종 판 기록이고 머리에 `simVersion`을 싣는다. 테스트는 골든의 `simVersion`이 코드의 값과 같은지, 해시와 기록이 완전히 같은지를 본다. 골든을 다시 만드는 명령은 코드의 `simVersion`이 골든의 값보다 클 때만 쓴다. 그래서 결과를 바꾼 변경은 `simVersion`을 올리고 골든을 다시 만들어야만 초록이 된다.

## Considered Options

- **다항식·파데 근사**: 코드가 짧고 분기가 없다. 그러나 살상 확률·코슈미더·토블러의 값이 데모와 눈에 띄게 달라질 수 있어 동등성 테스트의 허용 오차를 넓히거나 수치를 다시 맞춰야 하고, 정밀도의 기준이 "우리가 고른 계수"뿐이다.
- **사람이 플레이한 기록을 골든으로**: 현실적인 입력이지만 UI가 완성돼야 만들 수 있고 결과가 바뀔 때마다 다시 플레이해야 한다. 각본 입력은 첫 작업부터 쓸 수 있고 다시 만들기가 명령 하나다. 사람 플레이 기록은 M1 끝의 사람 검수 때 한 판만 더한다.
- **`simVersion`을 커밋 해시로 / CI의 diff 검사로 강제**: 커밋 해시는 결과가 안 바뀐 변경에도 옛 기록을 무효로 만든다. diff 검사는 CI 전용 스크립트가 하나 더 필요하다. 골든 머리의 값과 견주는 테스트 하나로 같은 강제가 된다.

## Consequences

- fdlibm 가운데 시뮬레이션이 실제로 쓰는 함수만 옮긴다. 새 초월 함수가 필요해지면 포팅을 더하고 비트 출력 표에 넣는다.
- 가우시안 난수도 내장 `Math.log`/`Math.cos` 대신 결정적 수학으로 만든다.
- mock 지형 생성기의 결과도 골든 머리의 지형 해시로 묶인다. 지형 생성이 달라지면 `simVersion`을 올린다.
- 화면 픽셀은 이 강제 밖이다. 렌더러는 투영 수학만 단위 테스트하고 생김새는 사람 검수가 본다.
