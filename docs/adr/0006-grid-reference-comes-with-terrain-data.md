# 방안 기준은 지형 자료에 딸려 오고, 시뮬레이션은 국지 미터만 쓴다

PRD 7.2는 가상 방안좌표를 "실제 MGRS로 교체 검토"라고만 했고 11.2는 어느 쪽인지 적지 않은 채 결정됨으로 표시했다. M1은 가상 방안좌표(찰리호텔, 8자리)를 데모 그대로 유지한다. 대신 M2에서 실제 지형이 들어올 때 시뮬레이션·입력 기록·교신 문법을 고치지 않도록, 방안 기준(원점의 동·북 값과 방안 문자)을 코드 상수가 아니라 지형 원천이 내주는 지형 자료의 일부로 둔다. 시뮬레이션 내부 위치는 국지 미터(x 동, y 북)뿐이고 위경도·MGRS 대를 모른다. 방안좌표 숫자는 경계(위치 송신·위치 보고 입력과 교신 사건의 슬롯)에서만 나타나며, 미터와 4+4자리 사이 변환은 `sim/` 안의 순수 함수 한 쌍 한 곳에만 있다(좌표자·지도 표시도 같은 함수). 방안 문자는 입력도 슬롯도 아니고, 문장을 만들 때 호출부호처럼 따로 넘겨 음성 문자 읽기로 붙인다.

## Considered Options

- **M1부터 MGRS**: 붙일 실제 땅이 없어 가짜 MGRS가 되고, 전장 위치(M2 결정)를 미리 박게 된다.
- **방안 기준을 `sim/`의 상수로**: 데모와 같지만 M2에서 지형을 바꾸면 시뮬레이션 코드와 `simVersion`이 함께 바뀐다.
- **방안 문자를 교신 문법 데이터의 고정 낱말로(데모 그대로)**: 전장이 바뀌면 문구 자료를 고쳐야 한다. 문자는 낱말이 아니라 전장의 값이다.
- **방안 문자를 입력·슬롯으로**: 전장이 100 km 방안 하나 안에 있는 동안은 플레이어가 고를 것이 없고 입력 기록 형식만 넓어진다.

## Consequences

- 지형 자료는 전장 전체(포대 위치 포함)가 100 km 방안 하나 안에 들어가는 방안 기준을 내줘야 한다. 테스트로 지킨다. M2 전장이 방안 경계를 걸치면 그때 입력 기록 `format`을 올려 문자를 입력에 싣는다.
- 정밀도는 8자리(10 m) 하나다. 미터→좌표는 버림, 좌표→미터는 칸 중심(+5 m). MGRS 8자리와 같은 규칙이라 읽기 규칙과 입력기는 M2에서 그대로 쓰인다.
- 실제 지형을 국지 미터 평면으로 펴는 일(투영)과 도북·자북 편차는 M2의 지형 원천 쪽 일이다. M1의 방위각은 모두 도북 기준이다.
- ADR 0004의 문장 만들기 인자가 하나 늘어난다: `(말한 쪽, 종류, 슬롯 값, 끝말)` + 호출부호 + 방안 문자.
