# 음성 입력은 기기 안에서 도는 공개 모델로 열린 양식의 낱말만 듣고, 브라우저 내장 인식은 쓰지 않는다

교신은 닫힌 낱말 집합이고 수를 한 자리씩 읽는다("넷오아홉아홉"). 그래서 음성 입력의 인식기는 들을 낱말을 줄 수 있는 것으로 골랐다: 기기 안에서 도는 공개 모델 vosk small-ko(Apache-2.0)에 그 순간 열려 있는 양식의 낱말만 준다. 브라우저 내장 인식은 받을 것이 없는데도 쓰지 않는다.

고른 근거는 합성 음성으로 잰 값이다(기준 데스크톱, 문장 25개 × 빠르기 둘). 사람 목소리로는 재지 않았다. 소유자가 녹음을 프로젝트 뒤로 미뤘기 때문이다. 그래서 이 선택은 사람 검수에서 뒤집힐 수 있고, 인식기를 음성 입력 이음매 뒤에 두어 바꿀 곳이 어댑터 하나가 되게 했다.

## Considered Options

- **브라우저 내장 인식, 기본 모드**: 내려받을 것이 없고 가장 빠르다. 그러나 최종 결과가 100번 가운데 36번만 왔고, 수를 제멋대로 적으며("하나 120", "넷050-3009"), 들을 낱말을 줄 길이 없고, 소리를 브라우저 회사의 서버로 보낸다.
- **브라우저 내장 인식, 기기 안 모드**: 낱말 치우침이 있는 유일한 내장 모드다. 한국어 언어 팩 설치가 끝나지 않아 재지 못했다.
- **Whisper tiny·base**: 기준 데스크톱에서 문장 하나에 3–15초이고 교신 낱말을 다른 낱말로 적으며 헛말이 나온다.

## Consequences

- 의존성 하나(`vosk-browser`, 2022년 뒤로 새 판이 없다)와 처음 한 번의 82 MiB 내려받기를 값으로 치른다. 모델은 저장소에 넣지 않고 받아서 둔다. 로그인 없이 받는 공개 라이선스 자료라 ADR 0013과 어긋나지 않는다.
- 모델 어휘에 없는 교신 낱말은 모델에 있는 조각으로 나눠 준다("효력사" → "효력 사"). 교신 문법 데이터에 낱말을 더하면 이 조각을 다시 확인해야 한다.
- 자동 테스트는 인식기를 돌리지 않는다. 가짜 인식기가 낸 글로 돌고, 인식기가 실제로 무엇을 듣는지는 사람 검수가 본다.
- 휴대폰에는 음성 입력을 내놓지 않는다(속도와 메모리를 잰 값이 없다).
- 다시 여는 때: 소유자의 녹음으로 잰 값이 이 선택을 뒤집을 때, 브라우저 내장 인식의 기기 안 모드를 잴 수 있게 될 때, `vosk-browser`가 새 브라우저에서 돌지 않게 될 때.
- 소리를 기기 밖으로 보내는 인식기를 끼우려면 소유자의 결정과 화면의 알림이 먼저 있어야 한다.
