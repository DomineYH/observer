# 시나리오와 포 프로파일은 JSON으로 옮길 수 있는 TS 상수로 번들에 싣고 CI에서만 검증한다

PRD 7.2는 시나리오를 "JSON 시나리오 파일", 포 프로파일을 "포 프로파일 JSON"으로 그렸다. M3는 둘과 실전 수치를 `content/`의 TS 상수로 둔다(함수 없이 JSON으로 그대로 옮길 수 있는 값만, ADR 0004와 같은 꼴). 시나리오는 한 전장 위에서 한 판에 주어지는 자료이고 글은 배치에 둔다. 배치 하나가 파일 하나이고 그 안에서 시나리오 자료, 증원, 글, 지형 참조의 자리가 갈린다. 모든 배치는 차례 있는 배치 목록으로 번들에 실리고 따로 받지 않는다. 검증은 세 겹이고 모두 CI에서 돈다: 형식은 타입 검사, JSON으로 옮길 수 있음과 유한한 수는 왕복 테스트, 가리키는 것·범위·글과 자료의 짝·기본 포의 사거리는 내용 검증. 실제 지형의 `배치` 테스트는 목록의 모든 배치에 돈다. 앱은 실행 때 자료를 검사하지 않고 받는 중·오류 화면도 없다.

## Considered Options

- **`.json` 파일을 번들에 가져오기**: PRD의 글 그대로다. 그러나 TypeScript가 가져온 JSON의 문자열을 `string`으로 읽어, 타입 검사 대신 손으로 쓴 형식 검사기가 필요하다(스키마 라이브러리를 더하지 않는다). 좌표를 왜 그렇게 두었는지 적는 주석도 쓸 수 없다. JSON이 주는 것(TS가 아닌 쪽이 읽기, 실행 때 밖에서 들어오는 시나리오)은 M3에 쓸 곳이 없다: 서버 재생 검증은 같은 TS 코드를 쓰고 편집기와 사용자 제작은 범위 밖이다.
- **지형 파일처럼 따로 받기**: 배치 하나는 수 KB인데 기대값, 받기 한도, 오류 화면을 한 벌 더 만들게 되고, 훈련·표준 화면에 새로 보이는 것이 생긴다.
- **앱이 시작할 때도 검사하기**: 번들에 든 자료는 CI를 지난 그 자료라, 일어날 수 없는 실패를 위해 화면을 만든다.
- **자료와 글, 증원을 다른 파일로**: 배치는 시나리오와 1:1이라 짝을 맞추는 검사만 는다. "글만 바뀌면 시나리오 버전은 그대로"는 파일 수가 아니라 무엇을 재는가로 지켜진다.
- **다른 시나리오의 값을 펼쳐 쓰기**: 한 시나리오를 고치면 다른 시나리오의 내용이 버전을 올리지 않은 채 따라 바뀐다.

## Consequences

- 형식을 바꾸는 일은 타입을 고치는 일이다. JSON 파일이 필요해지면(편집기, TS가 아닌 서버) 옮기는 일은 복사이고, 그때 형식 검사기를 쓴다.
- 접근로는 열쇠 있는 묶음이고 열쇠는 영문 대문자 한 글자다. 상태 해시는 접근로를 열쇠 글자의 알파벳 차례(A = 1 … Z = 26)로 읽는다. 적은 차례는 화면에 보이는 차례일 뿐이다.
- 배치 목록에 없는 파일, 내용 규칙을 어긴 자료는 필수 검사가 막는다. 플레이어에게 닿는 실패는 없다.
- 한 전장의 벌채 원 목록은 그 전장에 놓인 모든 배치의 관측소의 합집합과 같아야 한다. 새 벌채지는 지형 판을 올리고 그 전장의 골든 기록을 다시 만들게 한다.
- 새 시나리오를 쓰는 순서는 `src/content/README.md`에 있다.
- 자료의 내용이 버전과 어긋나지 않게 지키는 장치는 ADR 0009가, 실전 자료 판을 재생 자료에 싣는 법은 ADR 0019가 적는다([결정성과 버전](https://github.com/DomineYH/observer/issues/126)).
