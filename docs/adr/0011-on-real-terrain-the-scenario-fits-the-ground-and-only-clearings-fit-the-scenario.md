# 실제 지형에서는 시나리오가 땅에 맞추고, 벌채지만 땅이 시나리오를 따른다

mock 생성기는 시나리오의 관측소와 아군 진지 고지에 맞춰 땅을 만든다. 실제 땅은 그렇게 만들 수 없고, 한국 산지는 대부분 숲이라 데모의 숲 규칙(12–17 m, 불투명)과 눈높이를 그대로 두면 관측소에서 보이는 땅이 적다. 숲 모델과 데모 수치는 바꾸지 않고, 방향을 뒤집는다: 실제 지형에서는 시나리오의 좌표(관측소, 아군 진지, 접근로, NAI, 전선, 포대, 보급 도로)를 손으로 땅에 맞춰 놓는다. 땅이 시나리오를 따르는 예외는 벌채지 하나다. 계획 관측소와 예비 관측소(숲에 놓인 아군 진지도) 둘레의 숲 칸만 지형 가공 때 트인 땅으로 바꾼다. 벌채 원 목록은 가공 설정에 사본으로 적고 수용 테스트가 배치와 묶는다. 전장별 배치는 mock의 `base@1`과 다른 시나리오 식별자를 갖는다(문경은 `base-mungyeong@1`).

## Considered Options

- **벌채 원을 배치와 가공 설정 두 곳에 손으로 적고 믿기**: 묶는 테스트가 없어 가볍지만, 관측소 좌표를 고칠 때 벌채지가 어긋나도 아무것도 알리지 않는다.
- **실제 지형의 숲 높이를 낮추거나 숲 투과 규칙을 두기**: 시야는 넓어지지만 데모 수치나 시뮬레이션 규칙을 옮긴다. 시제품 3차가 벌채지와 손 배치만으로 접근로 기준을 넘겨 쓰지 않는다.
- **재배치를 `base`의 `version` 2로**: 식별자가 하나로 남지만 버전은 같은 배치의 고친 판을 뜻하므로, mock의 `base`가 고쳐질 때 번호가 엉킨다. 다른 땅의 배치는 다른 시나리오다.

## Consequences

- 배치의 좌표가 바뀌면 시나리오 버전이 오르고, 관측소가 움직이면 벌채 원이 바뀌어 지형 판도 오른다. 둘 다 실제 지형 골든 ⑤만 다시 만든다.
- 벌채지는 시뮬레이션 규칙이 아니라 지형 자료의 일부다. NAI와 접근로에는 두지 않는다.
- 싸움이 벌어지는 곳이 데모보다 멀어질 수 있다. 데모 정합 두 칸 목록의 "달라져도 되는 것"이다.
